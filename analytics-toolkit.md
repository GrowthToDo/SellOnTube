## Microsoft Clarity — Behavioral Analytics Detail

Clarity (row 6 above) is free, no traffic limits, no sampling: session recordings, heatmaps
(click/scroll/area), and smart signals (rage clicks, dead clicks, quick-backs). GA4 tells you
*what* happened; Clarity tells you *why* — the layer GA4 can't provide.

**Project ID:** `w3uumrqmgd` · **Dashboard:** https://clarity.microsoft.com/projects/view/w3uumrqmgd/
**Script:** `src/components/common/Analytics.astro` (async, main-thread — not Partytown, Clarity
needs main-thread access for recordings) · **Data retention:** 30 days (free tier) · auto-masks
sensitive inputs, no PII collected.

**Where it applies, per content pillar:**

| Pillar | What Clarity reveals | Act on |
|---|---|---|
| Microtools | Drop-off points mid-workflow, whether Gemini output is read or ignored, rage clicks on non-interactive elements | Simplify fields users hesitate on; add copy/expand buttons where dead clicks cluster on result text |
| pSEO pages | Scroll depth to the CTA/diagrams, quick-back rate (content/intent mismatch) | Move the CTA earlier if scroll drops before it; compare niches to find which templates resonate |
| Blog posts | Scroll depth per post, clicks on inline `toolCta` links vs the banner | Rework hooks if scroll is consistently <50%; double down on whichever CTA style gets clicks |
| Conversion path | Session recordings on `/pricing`, rage/dead clicks, the page sequence before a cal.com booking | Recordings of "almost-booked" visitors (reached pricing, left) show the actual friction point |

**Weekly metrics to pull:** scroll depth on blog posts, dead clicks on tool pages, site-wide rage
clicks, quick-back rate on pSEO pages, session recordings on the pricing page, tool completion rate
(Clarity recordings + GA4 events).

**Access:** `clarityPlaybackURL` / `clarityHeatmapURL` / `claritySessionId` flow into GA4 as custom
dimensions, queryable via `mcp_seo_server.py` alongside traffic/engagement data. For deeper cuts,
export CSVs from the dashboard's Recordings/Heatmaps/Insights tabs.

## How to Reuse This Toolkit for a New Website

### Step 1: Google Setup
1. Create a Google Cloud project and enable: Analytics Data API, Search Console API, Indexing API
2. Create a service account and download `credentials.json`
3. Add service account as Viewer in GA4 and Owner in GSC
4. Update `GA4_PROPERTY_ID`, `GSC_SITE_URL`, and `CREDENTIALS_PATH` in `mcp_seo_server.py`

### Step 2: Bing Setup
1. Create a Microsoft account and add site to [Bing Webmaster Tools](https://www.bing.com/webmasters/) (import from GSC is easiest)
2. Generate an API key from Bing Webmaster Settings
3. Add `BING_WEBMASTER_API_KEY` to `.env` and `.mcp.json`

### Step 3: Microsoft Clarity
1. Create a project at [clarity.microsoft.com](https://clarity.microsoft.com/)
2. Add the tracking script to your analytics component (replace project ID)
3. Link to GA4 in Clarity Settings > Setup > Google Analytics integration

### Step 4: IndexNow
1. Generate a key at [indexnow.org](https://www.indexnow.org/)
2. Host the key as a `.txt` file at site root (e.g., `/your-key.txt`)
3. Add `INDEXNOW_KEY` to `.env` and `.mcp.json`

### Step 5: DataForSEO (optional, paid)
1. Sign up at [dataforseo.com](https://dataforseo.com/)
2. Add `DATAFORSEO_LOGIN` and `DATAFORSEO_PASSWORD` to `.env` and `.mcp.json`

### Step 6: Ahrefs (optional, free tier)
1. Sign up for Ahrefs Webmaster Tools at [ahrefs.com/webmaster-tools](https://ahrefs.com/webmaster-tools)
2. Verify site ownership
3. Run crawls and export CSVs for analysis

### Step 7: Site Health Tools
No setup needed. The broken link checker, meta tag auditor, internal link mapper, and schema validator work by crawling the live site. Just update the base URL in `mcp_seo_server.py`.
